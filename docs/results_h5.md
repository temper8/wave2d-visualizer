# Спецификация формата `results.h5` (Wave2D)

Статус: **черновик**. Документ описывает фактическую структуру файлов Wave2D,
полученную инспекцией реальных данных (`Globus`, `FT2`), а не предполагаемую.
Физическая интерпретация величин и единицы измерения здесь **не** фиксируются —
это отдельный блокер (P0), см. раздел «Открытые вопросы».

Источники:

- `data/wave2d/Globus/results.h5`
- `data/wave2d/FT2/results.h5`

## 1. Общие сведения

- Контейнер: HDF5 (`h5py`), режим — только чтение.
- Корневые атрибуты (`/`) отсутствуют.
- Версия формата в файле **не записана** (нет `format_version`).
- Все двумерные поля хранятся как массивы `(Nr, Msmax)` в координатах
  `(rho, theta)`; `rho` — первая ось (радиус), `theta` — вторая (угол).

## 2. Размеры сетки (`/run_params/w2grid`)

Размеры **различаются между ранами**, их нельзя хардкодить — только читать из атрибутов.

| Атрибут   | Globus | FT2  | Тип    | Смысл (наблюдаемый) |
|-----------|-------:|-----:|--------|---------------------|
| `Nr`      | 361    | 101  | int32  | число радиальных точек (физическая область) |
| `Nrmargin`| 397    | 111  | int32  | число точек `coord/rho` (физическая область + margin) |
| `Msmax`   | 1024   | 512  | int32  | число угловых точек (вторая ось всех 2D-полей) |
| `Mmax`    | 144    | 64   | int32  | число сохраняемых азимутальных мод |
| `Nmax`    | 1734   | 774  | int32  | (смысл не установлен — открытый вопрос) |
| `nphi1`   | -14    | -122 | int32  | тороидальное мод. число (нижняя граница) |
| `nphi2`   | -14    | -122 | int32  | тороидальное мод. число (верхняя граница) |
| `nphistep`| 1      | 1    | int32  | шаг по `nphi` |

Инварианты:

- `Nrmargin >= Nr` (margin — продолжение радиальной сетки за физическую границу).
- Форма любого 2D-поля: `(Nr, Msmax)`.
- Длина `coord/rho`: `(Nrmargin,)`.

## 3. Именование групп `nphi`

Имя группы строится из `nphi1`:

```python
name = f"nphi-{abs(n):03d}" if n < 0 else f"nphi{n:03d}"
# nphi1=-14  -> "nphi-014"
# nphi1=-122 -> "nphi-122"
# nphi1=5    -> "nphi005"
```

Внутри группы есть атрибут `nphi` (int32), равный `nphi1`.

## 5. Опциональность узлов

Наблюдаемые расхождения между ранами:

| Узел | Globus | FT2 | Комментарий |
|------|:------:|:---:|-------------|
| `coord/{X,Y}` | + | + | полная координатная сетка |
| `<group>/{X,Y}` внутри `di_tensor_2D`, `flux_surf_2D`, `geometry_2D`, `magnt_fld_2D`, `plasma_par_2D`, `resonance_2D`, `wkb_2D` | + | − | **опциональны**, дублируют `coord` |
| `nphi-XXX/field_2d/*` | + | + | обязательная полезная нагрузка |

Правила чтения:

- **Не опираться** на наличие `<group>/X`, `<group>/Y`. Использовать
  `coord/X`, `coord/Y`, `coord/rho` как единственный надёжный источник геометрии:
  она общая для всех групп по `nphi`.
- Присутствующие `<group>/X`, `<group>/Y` равны `coord/X`, `coord/Y` в точках,
  где они не равны нулю; вне области определения заполнены `0` (≈0.3 % точек).
- Узел `nphi-XXX/grid_2d/*` — **устаревший** (встречается в старых файлах,
  напр. Globus); не используется, при наличии игнорировать.

## 7. Инварианты (проверены на Globus и FT2)

1. Форма всех 2D-полей = `(Nr, Msmax)`.
2. `len(coord/rho) == Nrmargin`.
3. `coord/rho[Nr-1] == a0` (физическая граница — на радиусе `a0`).
4. `coord/rho[-1] == 1.1 * a0` (margin простирается до `1.1·a0`).
5. Физическая радиальная область — `coord/rho[:Nr]`; остаток — margin.
6. `coord/X`, `coord/Y` — полные 2D-сетки формы `(Nr, Msmax)`.
7. Присутствующие `<group>/{X,Y}` равны `coord/{X,Y}` там, где не нулевые.
8. Атрибут `nphi` группы равен `nphi1` из `/run_params/w2grid`.

## 8. Открытые вопросы

- **Единицы.** `coord/rho`, `coord/X`, `coord/Y`, `geometry_2D/R` — единицы не
  установлены. Наблюдения: `coord/rho[Nr-1] == a0` и `coord/rho[-1] == 1.1·a0`
  для обоих ранов, т.е. `rho` масштабирован как доля `a0`. При этом `R0` у ранов
  отличается в ~6.7 раза (1.57 vs 10.6) при близких `a0` — требует подтверждения
  физиком (блокер P0).
- **`Mmax` и `Nmax`.** Смысл не установлен.
- **Маскирование `<group>/X,Y`.** Заполнение нулём вне области — намеренное или
  артефакт записи?
- **Версия формата.** Отсутствует `format_version`; при эволюции формата стоит
  добавить корневой атрибут.
- **`results_FT2.h5` vs `results.h5`.** Второй файл — отдельная конфигурация или
  параметр ридера? (см. TODO «Открытые вопросы»)

## 9. Рекомендации для адаптера

- Размеры брать **только** из `/run_params/w2grid`, не хардкодить.
- Имя группы `nphi` формировать из `nphi1` (см. §3).
- Геометрию брать из `coord/{X,Y,rho}` (общая для всех групп по `nphi`);
  `<group>/{X,Y}` и устаревший `grid_2d` игнорировать.
- Радиальную сетку обрезать до `[:Nr]`; не использовать `coord/rho` целиком.
- Чтение массивов — ленивое, по требованию (`h5py`), крупные датасеты не грузить целиком.
- Типы: `float64` для вещественных полей, `complex128` для `Ex/Ey/Ez`, `di_tensor_2D`,
  `wkb_2D`.
