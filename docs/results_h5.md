# Спецификация формата `results.h5` (Wave2D)

Статус: **черновик** — читательская спецификация.

- **Канон/оригинал:** [`docs/hdf5_schema.md`](hdf5_schema.md) — описывает формат
  со стороны продюсера (`hdf5_writer.f90`, `hdf5_manager.f90`): состав групп,
  смысл датасетов и атрибутов, правила объединения серии по `nphi`. Это
  **источник истины**; при любом расхождении верить оригиналу.
- Этот файл — **читательская** записка: наблюдения по реальным файлам,
  инварианты, подводные камни, рекомендации адаптеру. Он не дублирует семантику
  из оригинала, а уточняет её по факту.
- Смежный формат: [`docs/elmfire_h5.md`](elmfire_h5.md).

Проверенные источники данных:

- `data/wave2d/Globus/results.h5`;
- `data/wave2d/FT2/2026-09-23_21-58-05/results.h5` — **общий** файл серии;
- `data/wave2d/FT2/2026-09-23_21-58-05/tasks/<nphi>/results.h5` — файлы задач;
- `data/wave2d/FT2/2026-09-23_21-56-46/tasks/Nr+051/results.h5`.

## 1. Общие сведения

- Контейнер: HDF5, модуль `h5py`, режим — только чтение.
- **Корневой атрибут `version`** — версия схемы, документирована в оригинале
  (раздел «Версия формата» в [`hdf5_schema.md`](hdf5_schema.md)), пишется один
  раз при создании файла:
  - новые файлы (сборка FT2) — `f.attrs['version'] = b'0.9'` (string/bytes);
  - старые файлы (Globus) — атрибут отсутствует (созданы до версионирования),
    поэтому **наличие `version` проверять** перед чтением.
- Все 2D-поля хранятся как `(Nr, Msmax)`: ось 0 — радиальная (`rho`), ось 1 —
  полоидальная (`theta`). Пример: `f['coord/X'][ir, itheta]`.
- Типы: вещественные — `float64`, комплексные — `complex128`.

## 2. Размеры сетки (`/run_params/w2grid`)

Размеры **различаются между прогонами** — читать только из атрибутов, никогда
не хардкодить.

| Атрибут   | Globus | FT2 (2026-09-23) | Тип в файле задачи |
|-----------|-------:|-----------------:|--------------------|
| `Nr`      | 361    | 51               | int32 |
| `Nrmargin`| 397    | 56               | int32 |
| `Msmax`   | 1024   | 128              | int32 |
| `Mmax`    | 144    | 16               | int32 |
| `Nmax`    | 1734   | 198              | int32 |
| `nphi1`   | −14    | 122              | int32 |
| `nphi2`   | −14    | −122             | int32 |
| `nphistep`| 1      | −61              | int32 |

- `Nmax == 6*(2*Mmax + 1)` (было открытым вопросом — подтверждено для обоих
  ранов: `6*289=1734`, `6*33=198`).
- Инварианты: `Nrmargin >= Nr`, форма любого 2D-поля `(Nr, Msmax)`,
  `len(coord/rho) == Nrmargin`.

## 3. Файл задачи и общий файл серии

Оригинал (`hdf5_schema.md`, раздел «Общий файл для серии по `nphi`») описывает
два вида файлов — здесь важные для ридера следствия:

- **Файл задачи** (`tasks/<задача>/results.h5`): ровно **одна** группа
  `/nphi*`; в `/run_params/w2grid` записано `nphi1 == nphi2 == <мода>`,
  `nphistep == 1`.
- **Общий файл серии** (`<прогон>/results.h5`): несколько групп `/nphi*`
  (здесь — 5 мод `+000, +061, +122, −061, −122`); в `/run_params/w2grid`
  записан диапазон всей серии. Собирается лаунчером (`launcher/results.py`,
  `merge_nphi_results`): база — файл первой задачи, дальше дописываются
  группы `/nphi*` остальных.
- **Типы `nphi1/nphi2/nphistep` зависят от файла**: в общем файле серии —
  `int64`, в файле задачи — `int32`. Не предполагать тип, брать `int(...)`.
- Серия наблюдается не только по `nphi`: встречается задача `tasks/Nr+051`
  (варьируется `Nr`), при этом внутри файла задачи всё равно одна группа
  `/nphi*`.

**Правило чтения:** моду определять по атрибуту `nphi` группы, а не по имени
группы; не считать, что группа `/nphi*` одна.

## 4. Именование групп `nphi`

### 4.1. Канон (новые файлы, продюсер Wave2D)

```
'nphi' + знак ('+' при nphi >= 0, '-' при nphi < 0) + |nphi| с ведущими нулями до 3 цифр
```

| nphi | имя группы |
|-----:|------------|
| −14  | `nphi-014` |
| 0    | `nphi+000` |
| +122 | `nphi+122` |

**Python:**

```python
def nphi_group_name(nphi: int) -> str:
    """Каноническое имя HDF5-группы для тороидального числа nphi."""
    sign = "+" if nphi >= 0 else "-"
    return f"nphi{sign}{abs(nphi):03d}"
```

**Fortran (продюсер):** `write(name, '(A,SP,I4.3)') 'nphi', nphi` — `SP` печатает
`+`, `I4.3` даёт `+014`/`-014`/`+000`; корректно лишь при `abs(nphi) <= 999`.

### 4.2. Legacy (уже сгенерированные файлы)

В существующих файлах встречается схема без знака у неотрицательных —
например, Globus `nphi-014`, FT2 `nphi+122` (канон). Ридер обязан принимать
**оба** варианта и **всегда** сверять значение с атрибутом `nphi` группы.
Регулярки для парсинга:

```
^nphi([+-])(\d{3,})$    # канон (nphi+014 / nphi-014)
^nphi-(\d{3,})$         # legacy отрицательный (nphi-014)
^nphi(\d{3,})$          # legacy положительный/ноль (nphi014)
```

> Сортировка: в ASCII `'+'` (0x2B) < `'-'` (0x2D), поэтому `ls`/`h5ls` покажут
> сначала `nphi+…`, потом `nphi-…`. Числовой порядок — только сортировкой по
> атрибуту `nphi`.

## 5. Карта групп

Полная семантика датасетов — в [`hdf5_schema.md`](hdf5_schema.md). Ниже —
карта для навигации ридера:

```
/
├── coord/                 X, Y (Nr,Msmax) float64; rho (Nrmargin,) float64
├── di_tensor_2D/          L, aMX, aTT, eps, eta, gee   (complex128)
├── flux_surf_2D/          psi, theta_deg, theta_pi_diff
├── geometry_2D/           Jc, Nh, R, cosb, sinb
├── magnt_fld_2D/          Bpol, Btor, Btot, Nparall, alpha, jp
├── plasma_par_2D/         Te, Ti, VRe, VRi, coll_rate, damp_rate, ne
├── resonance_2D/          w0_wce, w0_wlh, w0_wpe, w0_wuh, Xcutoff_at_0, PolRes_at_0
├── wkb_2D/                Nrho1, Nrho2                     (complex128)
├── run_info/system/       только атрибуты
├── run_params/            только атрибуты: w2grid, plasma, density, temperature, kngrid
└── nphi±XXX/              attr nphi int32
    └── field_2D/          Ex, Ey, Ez (complex128); Ea (float64)
```

## 6. Опциональные узлы

| Узел | Globus | FT2 | Комментарий |
|------|:------:|:---:|-------------|
| `<group>/{X,Y}` для 7 полевых групп | + | − | **опциональны**, дублируют `coord` |
| `nphi±XXX/grid_2d/*` | + | − | **устаревший**, игнорировать |

Правила чтения:

- **Не опираться** на наличие `<group>/X`, `<group>/Y`. Единственный надёжный
  источник геометрии — `coord/X`, `coord/Y`, `coord/rho` (общая для всех мод).
- Присутствующие `<group>/{X,Y}` равны `coord/{X,Y}` там, где не нулевые; вне
  области определения заполнены `0`.
- Узел `grid_2d` не использовать.

## 8. Инварианты (проверены на Globus и FT2)

1. Форма всех 2D-полей = `(Nr, Msmax)`.
2. `len(coord/rho) == Nrmargin`.
3. `coord/rho[Nr-1] == a0` (физическая граница на радиусе `a0`).
4. `coord/rho[-1] == 1.1 * a0` (margin до `1.1·a0`).
5. Физическая радиальная область — `coord/rho[:Nr]`; остаток — margin.
6. `coord/X`, `coord/Y` — полные 2D-сетки `(Nr, Msmax)`.
7. Присутствующие `<group>/{X,Y}` равны `coord/{X,Y}` там, где не нулевые.
8. `Nmax == 6*(2*Mmax + 1)`.
9. В файле задачи атрибут `nphi` группы равен `nphi1` из `/run_params/w2grid`.

## 9. Особенности и подводные камни

1. **Незаполненные точки = `0`, а не `NaN`.** Оригинал говорит «не заполнены».
   Фактически это нули: `numpy.isnan` бесполезен, надо сравнивать с `0`.
   Относится к строке `ir = 0` и к опциональным `<group>/{X,Y}`.
2. **Магнитная ось (`ir = 0`) неоднородна по группам:**
   - `wkb_2D/Nrho1, Nrho2` — вся строка `ir = 0` равна `0+0j`;
   - `flux_surf_2D/psi, theta_deg` — на оси не нули, а машинный мусор
     порядка `1e-11…1e-13` (физически `≈0`);
   - `magnt_fld_2D`, `geometry_2D`, `resonance_2D`, `di_tensor_2D` — на
     `ir = 0` ненулевая **только первая полоидальная точка**, остальные `0`;
   - **`plasma_par_2D` — исключение:** на `ir = 0` в столбцах `1…Msmax-1`
     лежит не нули, а мусор (линейные рампы: `Te = 45, 64.7, 84.4, …`).
     Осмысленна только точка `ir = 0, itheta = 0`
     (`Te = Te0`, `Ti = Ti0`, `ne = de0`). Читать ось лишь как `[0, 0]`.
3. **Размеры не хардкодить** — только из `/run_params/w2grid` (см. §2).
4. **Корневой атрибут `version`** документирован в оригинале («Версия формата»),
   но присутствует не во всех файлах: в Globus его нет, в FT2 — `0.9`. Наличие
   проверять перед чтением (см. §1).
5. **Типы атрибутов `w2grid` различны** (`int64` в общем файле серии, `int32`
   в задаче) — см. §3.

## 10. Пример чтения

```python
import h5py

path = ".../results.h5"
with h5py.File(path, "r") as f:
    nr = int(f["run_params/w2grid"].attrs["Nr"])
    ms = int(f["run_params/w2grid"].attrs["Msmax"])

    # полоидальные моды — по атрибуту nphi, а не по имени группы
    modes = {int(f[g].attrs["nphi"]): g for g in f if g.startswith("nphi")}

    # 2D-поле выбранной моды
    Ex = f[f"{modes[122]}/field_2D/Ex"][nr, ms]  # complex128

    # геометрия общая для всех мод — только из /coord
    X, Y, rho = f["coord/X"][()], f["coord/Y"][()], f["coord/rho"][()]
```

Пути к данным в проекте — только через `src/common/paths.py` (см. `AGENTS.md`),
не хардкодить `results.h5`.

## 11. Рекомендации адаптеру

- Размеры брать **только** из `/run_params/w2grid`.
- Моду определять по атрибуту `nphi`; имя группы — по канону §4, legacy
  принимать и сверять со значением атрибута.
- Геометрию брать из `coord/{X,Y,rho}`; `<group>/{X,Y}` и устаревший `grid_2d`
  игнорировать.
- Радиальную сетку обрезать до `[:Nr]`; `coord/rho` целиком не использовать.
- Ось (`ir = 0`) не читать без проверки; в `plasma_par_2D` — только `[0, 0]`.
- Чтение — ленивое (по требованию, `h5py`), крупные датасеты не грузить целиком.
- Типы: `float64` для вещественных полей, `complex128` для `Ex/Ey/Ez`,
  `di_tensor_2D`, `wkb_2D`.

## 12. Открытые вопросы

- **Единицы.** `coord/rho`, `coord/X`, `coord/Y`, `geometry_2D/R` — единицы не
  установлены. Наблюдения: `coord/rho[Nr-1] == a0` и `coord/rho[-1] == 1.1·a0`
  для обоих ранов, т.е. `rho` нормирован долей `a0`; при этом `R0` у ранов
  отличается в ~6.7 раза (1.57 vs 10.6) при близких `a0` — требует
  подтверждения физиком (блокер P0).
- **Мусор на оси в `plasma_par_2D`** — воспроизводится ли во всех прогонах или
  это артефакт конкретной сборки? Является ли `plasma_par_2D` единственной
  такой группой?
- **Маскирование `<group>/{X,Y}`** — заполнение нулём вне области намеренно
  или артефакт записи?
- **`results_FT2.h5` vs `results.h5`** — отдельная конфигурация или параметр
  ридера? (см. `TODO.md`, «Открытые вопросы»)
