# Спецификация формата `results.h5` (Wave2D)

Статус: **черновик** — читательская спецификация.

- **Канон/оригинал:** [`docs/hdf5_schema.md`](hdf5_schema.md) — описывает формат
  со стороны продюсера (`hdf5_writer.f90`, `hdf5_manager.f90`): состав групп,
  смысл датасетов и атрибутов, правила объединения серии по `nphi`. Это
  **источник истины**; при любом расхождении верить оригиналу.
- Этот файл — **читательская** записка: наблюдения по реальным файлам,
  инварианты, подводные камни, рекомендации адаптеру. Он не дублирует семантику
  из оригинала, а уточняет её по факту.
- Смежный формат: [`docs/elmfire_h5.md`](elmfire_h5.md).

Проверенные источники данных (формат `0.94`):

- `data/wave2d/FT-2_LH_smoke/2026-09-28_15-30-49/tasks/Nr+051/results.h5`;
- `data/wave2d/FT-2_LH_smoke_nphi/2026-09-28_15-31-35/results.h5` — **общий**
  файл серии (5 мод);
- `data/wave2d/FT-2_LH_smoke_nphi/2026-09-28_15-31-35/tasks/<nphi>/results.h5`.

## 1. Версия формата и поддержка

- Контейнер: HDF5, модуль `h5py`, режим — только чтение.
- **Корневой атрибут `format_version`** — строка версии схемы (`"0.94"`).
- **Поддерживается только новый формат.** Минимальная версия задана константой
  `src.wave2d.schema.MIN_FORMAT = (0, 94)` (строка `"0.94"`).
- Файлы старых схем (`0.9`…`0.93`) **не читаются**: раскладка групп и набор
  атрибутов в них другие. Чтение отклоняется с
  `src.wave2d.schema.UnsupportedFormatError` («формат не поддерживается»).
  Проверка — `ensure_supported()` / `ensure_supported_path()` / `open_results()`
  в `src/wave2d/schema.py`.
- Все 2D-поля хранятся как `(Nr, Msmax)`: ось 0 — радиальная (`rho`), ось 1 —
  полоидальная (`theta`). Пример: `f['grid/X'][ir, itheta]`.
- Типы: вещественные — `float64`, комплексные — `complex128`.
- Каждый датасет несёт строковый атрибут `units`; `1` — безразмерная величина
  (см. оригинал, раздел «Датасеты»).

## 2. Размеры сетки (`/input/w2grid`)

Размеры **различаются между прогонами** — читать только из атрибутов, никогда
не хардкодить.

| Атрибут   | FT-2_LH_smoke (Nr+051) | FT-2_LH_smoke_nphi (серия) | Тип |
|-----------|-----------------------:|---------------------------:|-----|
| `Nr`      | 51                     | 51                         | int32 |
| `Msmax`   | 128                    | 128                        | int32 |
| `Mmax`    | 16                     | 16                         | int32 |
| `Nmax`    | 198                    | 198                        | int32 |
| `nphi1`   | −122                   | 122                        | int64 |
| `nphi2`   | −122                   | −122                       | int64 |
| `nphistep`| 1                      | −61                        | int64 |

- `Nmax == 6*(2*Mmax + 1)` (`6*33 = 198`).
- Инварианты: форма любого 2D-поля `(Nr, Msmax)`;
  `len(grid/rho) == len(grid/psi) == Nr`.
- Фактические значения `grid/rho` для FT-2_LH_smoke_nphi: `0.0 … 8.0`
  (атрибут `units=cm`); `grid/psi`: `0.0 … 1.0` (`units=1`).
- Атрибут `Nrmargin` **удалён** из схемы (0.94): запас за `a0` остался только в
  легаси-ASCII выводе и вычисляется локально. Радиальную сетку больше **не надо**
  обрезать до `[:Nr]` — `grid/rho` уже длины `Nr`.

## 3. Файл задачи и общий файл серии

Оригинал (`hdf5_schema.md`, раздел «Общий файл для серии по `nphi`») описывает
два вида файлов — здесь важные для ридера следствия:

- **Файл задачи** (`tasks/<задача>/results.h5`): ровно **одна** группа
  `/fields/nphi*`; в `/input/w2grid` записано `nphi1 == nphi2 == <мода>`,
  `nphistep == 1`.
- **Общий файл серии** (`<прогон>/results.h5`): несколько групп `/fields/nphi*`
  (здесь — 5 мод `+000, +061, +122, −061, −122`); в `/input/w2grid` записан
  диапазон всей серии. Собирается лаунчером (`launcher/results.py`,
  `merge_nphi_results`): база — файл первой задачи, дальше дописываются
  группы `/fields/nphi*` остальных.
- Серия наблюдается не только по `nphi`: встречается задача `tasks/Nr+051`
  (варьируется `Nr`), при этом внутри файла задачи всё равно одна группа
  `/fields/nphi*`.
- Не у всех прогонов есть общий файл: например, у `FT-2_LH_smoke` есть только
  файл задачи (`tasks/Nr+051`) — run-level `results.h5` отсутствует. Ридеру
  стоит уметь откатываться на файл задачи.

**Правило чтения:** моду определять по атрибуту `nphi` группы, а не по имени
группы; не считать, что группа `/fields/nphi*` одна.

## 4. Именование групп `nphi`

### 4.1. Канон

```
'nphi' + знак ('+' при nphi >= 0, '-' при nphi < 0) + |nphi| с ведущими нулями до 3 цифр
```

| nphi | имя группы |
|-----:|------------|
| −122 | `nphi-122` |
| 0    | `nphi+000` |
| +122 | `nphi+122` |

**Python (реализовано в `src/wave2d/schema.py`):**

```python
def nphi_group_name(nphi: int) -> str:
    """Каноническое имя HDF5-группы для тороидального числа nphi."""
    sign = "+" if nphi >= 0 else "-"
    return f"nphi{sign}{abs(nphi):03d}"
```

Хелперы: `field_group(nphi)` → `/fields/nphi+122`;
`field_dataset(nphi, "Ea")` → `/fields/nphi+122/Ea`;
`nphi_modes(reader)` → `{nphi: путь группы}` по атрибуту `nphi`.

**Fortran (продюсер):** `write(name, '(A,SP,I4.3)') 'nphi', nphi` — `SP` печатает
`+`, `I4.3` даёт `+122`/`-122`/`+000`; корректно лишь при `abs(nphi) <= 999`.

> Сортировка: в ASCII `'+'` (0x2B) < `'-'` (0x2D), поэтому `ls`/`h5ls` покажут
> сначала `nphi+…`, потом `nphi-…`. Числовой порядок — только сортировкой по
> атрибуту `nphi`.

## 5. Карта групп

Полная семантика датасетов — в [`hdf5_schema.md`](hdf5_schema.md). Ниже —
карта для навигации ридера:

```
/
├── manifest/              только атрибуты: system, toolchain, run
├── input/                 только атрибуты: w2grid, plasma, temper, kngrid, dens
├── grid/                  rho (Nr,), psi (Nr,), X (Nr,Msmax), Y (Nr,Msmax)
├── geometry/              Jc, Nh, R, cosb, sinb
├── flux_surf/             theta_deg, theta_pi_diff
├── plasma/
│   ├── params/            Te, Ti, VRe, VRi, coll_rate, damp_rate, ne
│   ├── bfield/            Bpol, Btor, Btot, Nparall, alpha, jp
│   ├── dielectric/        L, aMX, aTT, eps, eta, gee          (complex128)
│   ├── resonance/         w0_wce, w0_wlh, w0_wpe, w0_wuh, Xcutoff_at_0, PolRes_at_0
│   └── wkb/               Nrho1, Nrho2                         (complex128)
└── fields/
    └── nphi±XXX/          attr nphi int32; Ex, Ey, Ez (complex128); Ea (float64)
```

## 7. Инварианты (проверены на FT-2_LH_smoke)

1. Форма всех 2D-полей = `(Nr, Msmax)`.
2. `len(grid/rho) == len(grid/psi) == Nr`.
3. `grid/rho` — 1D радиальная ось (порядок и длина совпадают с осью 0 полей);
   значения `0.0 … 8.0`, атрибут `units=cm`.
4. `Nmax == 6*(2*Mmax + 1)`.
5. В файле задачи атрибут `nphi` группы равен `nphi1` из `/input/w2grid`.
6. У каждого датасета есть строковый атрибут `units`.

## 8. Особенности и подводные камни

1. **Незаполненные точки = `0`, а не `NaN`.** Оригинал говорит «не заполнены».
   Фактически это нули: `numpy.isnan` бесполезен, надо сравнивать с `0`.
   Относится к строке `ir = 0`.
2. **Магнитная ось (`ir = 0`) неоднородна по группам:**
   - `plasma/wkb/Nrho1, Nrho2` — вся строка `ir = 0` равна `0+0j`;
   - `flux_surf/theta_deg` — на оси не нули, а машинный мусор порядка
     `1e-11…1e-13` (физически `≈0`);
   - `plasma/bfield`, `geometry`, `plasma/resonance`, `plasma/dielectric` — на
     `ir = 0` ненулевая **только первая полоидальная точка**, остальные `0`;
   - **`plasma/params` — исключение:** на `ir = 0` в столбцах `1…Msmax-1`
     лежит не нули, а мусор (линейные рампы). Осмысленна только точка
     `ir = 0, itheta = 0` (`Te = Te0`, `Ti = Ti0`, `ne = de0`).
3. **`grid/psi` — 1D**, а не 2D (раньше роль 2D-`psi` играл `flux_surf_2D/psi`,
   удалённый в 0.94). Если нужен вид `(R,Z)` — размножать по θ вручную.
4. **Размеры не хардкодить** — только из `/input/w2grid` (см. §2).
5. **Не у каждого прогона есть общий файл** — см. §3.

## 9. Пример чтения

```python
from src.wave2d.schema import (
    INPUT_W2GRID, GRID_X, GRID_Y, GRID_RHO, field_dataset, nphi_modes, open_results,
)

path = ".../results.h5"
with open_results(path) as f:                       # проверяет format_version >= 0.94
    w2grid = f.attrs(INPUT_W2GRID)
    nr, ms = int(w2grid["Nr"]), int(w2grid["Msmax"])

    # полоидальные моды — по атрибуту nphi, а не по имени группы
    modes = nphi_modes(f)                           # {nphi: "/fields/nphi+122", ...}

    # 2D-поле выбранной моды (complex128)
    Ex = f.array(field_dataset(122, "Ex"))

    # геометрия общая для всех мод — только из /grid
    X, Y, rho = f.array(GRID_X), f.array(GRID_Y), f.array(GRID_RHO)
```

Пути к данным в проекте — только через `src/common/paths.py` (см. `AGENTS.md`),
не хардкодить `results.h5`.

## 10. Рекомендации адаптеру

- Перед чтением вызывать `open_results()`/`ensure_supported()`; старые форматы
  не поддерживать (сообщение «формат не поддерживается»).
- Размеры брать **только** из `/input/w2grid`.
- Моду определять по атрибуту `nphi`; имя группы строить `nphi_group_name`.
- Геометрию брать из `grid/{X,Y,rho}`.
- `grid/rho` уже длины `Nr` — обрезать не нужно.
- Ось (`ir = 0`) не читать без проверки; в `plasma/params` — только `[0, 0]`.
- Чтение — ленивое (по требованию, `h5py`), крупные датасеты не грузить целиком.
- Типы: `float64` для вещественных полей, `complex128` для `Ex/Ey/Ez`,
  `plasma/dielectric`, `plasma/wkb`.

## 11. Открытые вопросы

- **Единицы и нормировка `grid/rho`/`grid/psi`.** По спеке `grid/psi = rho/a0`,
  но фактически `grid/rho[-1] = 8.0` при `a0 = 1.54`, а `grid/psi[-1] = 1.0`
  (`8.0/1.54 ≈ 5.2 ≠ 1`). Связь `rho`, `psi` и `a0` требует подтверждения
  физиком (блокер P0).
- **Согласованность с ELMFIRE.** `grid/rho` несёт `units=cm`; ELMFIRE читает
  `rho(cm)` — при интеграле следить за множителем 100 (блокер P0).
- **Мусор на оси в `plasma/params`** — воспроизводится ли во всех прогонах или
  это артефакт конкретной сборки?
