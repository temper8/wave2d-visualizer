## Контекст

MVP MultiView показывает вкладку группы текстовым списком. Для 2D-групп
(поля `(rho,theta)`/`(R,Z)`) нужна реальная отрисовка: несколько картинок
**рядом**, сеткой subplots, с **общей** нормировкой `vmin`/`vmax` — иначе
сравнение некорректно. Наложение 2D друг на друга смысла не имеет.

Сюда же переезжает шаг из P0 про поведение 2D при multi-select в
`DatasetView` (раньше был пунктом 1D-задачи).

## Шаги

- [ ] `renderers.draw_2d_grid(fig, items, *, comp)`: сетка subplots с общей
      нормировкой, подпись на каждой панели (источник + путь), colorbar на
      общий диапазон.
- [ ] 2D-вкладка `MultiView` рисует `draw_2d_grid` вместо текстового списка
      (список элементов с удалением сохранить).
- [ ] `DatasetView` при multi-select, где есть 2D/группы: определить поведение
      — показывать первый 2D-узел, сообщение «выберите один», или список
      атрибутов; без падений.
- [ ] Smoke вручную: 2D-группа с 2+ элементами → сетка с общей шкалой;
      разнородный выбор не роняет окно.

## Критерии готовности

- 2D-группа MultiView рисуется сеткой с общей нормировкой и подписями.
- Поведение 2D/смешанного multi-select в `DatasetView` определено.

## Риски / открытые вопросы

- **Сетка vs разность** `A−B` (общий вопрос — в
  [p2-multiview-compare-runs.md](p2-multiview-compare-runs.md), раздел
  «Открытые вопросы»).
- **Единицы/нормировка:** общая шкала осмысленна только при согласованных
  единицах; при разных — предупреждать.
- Память: снимки 2D уже лежат в `PlotItem`, дополнительных копий не делать.
